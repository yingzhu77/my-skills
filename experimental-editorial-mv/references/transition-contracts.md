# 场景交接合同

用于重要章节边界与同一主体的换观看方式。合同记录观众需要认出的关联和代码应共享的状态；并非要求所有转场无缝。先选转场类型，再判断哪些量必须连续。

| 类型 | 记录的成立条件 | 不必强求 |
|---|---|---|
| 音乐硬切 | 可听见的触发、切后焦点、意象/构图关系 | 坐标或速度连续 |
| 形状/方向匹配切 | 可识别的轮廓、主轴、方向或色块；明确对应主体 | 两张位图自动变形 |
| 连续几何转移 | 同一主体 ID，前后几何与遮挡；必要时速度 | 全部背景同样连续 |
| 材质转换 | 已出现内容成为何种新材料，保留的字/图/痕迹 | 无关装饰全部保留 |
| 布局预示/回收 | 前场提出的布局预期，后场赋予的内容或变化 | 精确逐像素匹配 |

## 一张边界记录

```text
boundary: 乐句/事件 ID + 实际秒数
kind: 上表的一种（可说明组合）
carrier: 主体 ID / 素材 ID / 轮廓 ID
before → after: 占据范围、主轴、遮挡、主色、动作方向
focus: 转场后首先应该看到什么
shared state: 连续类型需共享的参数/函数
music reason: 此时交接的可听见依据
```

无需给每次小图闪现写完整合同；优先处理动作结果交接、主导画面改变和材料状态改变。若转场后原主体完全不见，说明是有意终止还是实现遗漏。

## 连续类型的共享几何

在一个时间函数里覆盖边界前后，不分别在两个 scene 中重建“看起来差不多”的末态和初态。中性伪代码：

```text
carrierAt(t) → {id, x, y, w, h, angle, maskPath, material}
sceneBefore.draw(carrierAt(t), localContents)
sceneAfter.draw(carrierAt(t), developedContents)
```

若前后只有尺寸变化，共享矩形足够；若线条在边界后仍继续运动，需要检查方向和速度是否突变。速度可以有意撞停或换向，但应属于动作而不是两个 ease 重启造成的意外。内容焦点和裁切也属于身份：同一照片 ID 若突然换主体裁切，观众仍可能认为是新图片。

原例 [cycle.js:65–81](https://github.com/longruizhi2-beep/he-drowns-mv-v2/blob/d4b7a0dfaa0cb77cbf9ebc564fb1068ebd3a09d5/js/scenes/cycle.js#L65) 用同一 `x0/y0/w/h` 连接局部照片裁切、透明孔与空间视口；这是可复用的几何合同。纯 2D 可用同一路径连接主体、侵蚀孔和轮廓，属于新作品的适配。

## 材质转换保留已发生的内容

页面转为空间物体时，先让当前已完成页面成为其纹理，而不是更换一张视觉类似的图。原例 [end.js:169–184](https://github.com/longruizhi2-beep/he-drowns-mv-v2/blob/d4b7a0dfaa0cb77cbf9ebc564fb1068ebd3a09d5/js/scenes/end.js#L169) 保留污迹与页面，物体初始投影铺满画面，再让相机拉远。新的纯 2D 作品可让字成为裂线、图成为负形、散片成为新轮廓，但需要有可追认的内容载体；这种转换不是原例已有的通用 morph 系统。

P/I/3D 路径切换还要明确：何时页面烘成纹理，何时字体留屏幕层，何时全页填充停止遮住空间。透明孔是真实 alpha，不用黑色矩形假装洞。平面拼贴无需服从写实深度，但其层次规则应可辨认。

## 预示不等于无缝 morph

原例 [decon.js:217–236](https://github.com/longruizhi2-beep/he-drowns-mv-v2/blob/d4b7a0dfaa0cb77cbf9ebc564fb1068ebd3a09d5/js/scenes/decon.js#L217) 先画下章栏结构，再由 [cycle.js:37–86](https://github.com/longruizhi2-beep/he-drowns-mv-v2/blob/d4b7a0dfaa0cb77cbf9ebc564fb1068ebd3a09d5/js/scenes/cycle.js#L37) 显影内容；真实代码仍存在版面起始位移。可将它提炼成“观众先认识观看规则”，不能宣称原作在边界完全逐像素连续。

若新作选择加强连续性，提取一个共享 `layoutSpec/carrierAt` 再测边界。若选择匹配切，保持栏比例或主轴，允许一次明确切换。二者都可以成立。

## 检查边界的方法

正常速度连续看前后的动作与音乐，再取边界前、边界、边界后帧辅助定位。连续类型核对 ID、轮廓、裁切、位置/尺寸/角度和必要速度；硬切类型核对触发与焦点；材质类型核对保留下来的内容。测试 seek 到两侧得到相同状态，避免只有从头播放才成立。

边界前后是否需要停留由听感与视觉注意力决定。不要为了消除所有切口把合理的音乐硬切改成长交叉淡化，也不要用淡化掩盖一个承诺连续却重新摆位的主体。
