# 实验编辑 MV

把音乐组织成一本会运动、会改变形态和材质的杂志。继承参考项目的编排方法；根据新作品选择主题、意象、字体、节奏，以及 2D / 3D 表现方式。

## 从音乐到画面

1. 从用户素材和已有项目确定时长、主题、输出方式、文字语言与主要高潮。没有音乐时先做可替换的节奏原型并标明假设。模板支持浏览器实时播放与实时 WebM 录制。
2. 建立音乐事件、主体动作与意象回归表：记录时间、证据、乐句/分组、作用对象、动作发展与结果。候选歌词/起音、导演选择和实际听辨分别标明；BPM 本身不证明小节相位。
3. 选择少量会重复并改变含义的意象，并为新曲确定色组、背景材质与运动速度的依据。图形、字或照片改变观看功能、轮廓、材质或对象关系。日式编辑感来自竖排、跨页、明朝/黑体对照、图注和版面关系；文字语言遵循用户内容。纸白和红/青专色是可选示例，不是所有歌曲的默认主题。
4. 先做覆盖完整动作及一次接续的短样片，正常速度带音乐检查。让观众能追踪哪个主体发生变化、留下什么结果、下一动作如何接住它；安静停留和有目的的硬切可以成立。根据艺术方向选择纯 2D、摄影、2.5D 或 3D。
5. 长动作以乐句/语义进程推进，短反应叠加于其上。可信的底鼓、军鼓、踩镲可分工驱动不同动作；只有混音起音时保留该标签。硬切落在有理由的音乐事件，以意象关系编排预示和回忆。
6. 先检查主体变化、速度差异、可读时段及交接，再检查加载、同步、跳转和导出。依据本机测量调整尺寸；技术通过与审美判断分别报告。

## 核心实现约束

- 使用印刷引擎时，照片层 `P` 的颜色/透明度决定底图和背景；油墨层 `I` 用 RGB 表示 K/A/B 三印版覆盖率，输出颜色由印刷参数决定。
- 选择混合空间表现时，可用纸面孔露出 3D、3D 加网印在纸上、整页贴图进入 3D。替换引擎时检查相机、背景、主体、遮挡和共同动力的关系。
- 纯 2D 可让同一几何函数生成主体、遮罩和描边，以形变、显影、侵蚀或版式展开实现动作；摄影和 3D 均可为零。
- 使用纹理数组时，各层尺寸/格式一致，照片比例在几何中恢复。纹理层数与每帧可见对象数是不同限制。
- 场景参数和确定性噪声从歌曲时间计算；拖影使用前帧反馈。截图或不连续跳转时清空历史，需要一致拖影截图时按固定步长预热。
- MediaRecorder 组合画布视频流与 Web Audio 音频流，按实时长度录制。逐帧离线渲染需要额外实现。
- 原曲的 91 BPM、94 小节、19 音乐段落、51 渲染片段、歌词与海洋主题属于参考作品。新曲重新分析、编排；README 的「43 个采样点」指性能抽样。

## 可运行起点

在新目录运行本 skill 的脚本，将路径换成本机位置：

```powershell
python "<skill-dir>/scripts/scaffold.py" "<project-dir>"
node "<project-dir>/serve.js"
```

复制脚本不访问网络，不覆盖非空目录。浏览器打开服务器打印的 URL。模板含 20 秒原创合成节奏、6 张由代码生成的中性图形和 MIT 核心引擎；演示材质/空间转换、播放/暂停、拖动、画质与 WebM 录制。无框架和 npm 依赖，不分发照片、歌曲或字体素材。

这个四状态模板是渲染演示，成片按新曲重新编排。使用 `scaffold.py --motion-study <project-dir>` 可创建独立的纯 2D 动作示例：条带收紧为一道缝，沿同一边界张开、发展墨形并收束。它是基于原例方法的新示例，不含原曲音频或歌词。详见 [references/starter.md](references/starter.md)。

修改已有应用时按其结构集成。模板使用系统字体；正式作品引入字体后检查新文字的字形覆盖与许可。

## 交付检查

- 正常速度样片中，主体改变了什么，动作留下什么结果，下一动作接住什么？意象回归是否改变含义、轮廓或材质？
- 减去颗粒/闪光等装饰后，主体动作是否仍成立？静帧辅助检查字体和构图，不替代连续观看。
- 关键动作是否落在可信的音乐事件？相同时间能否复现，包括拖影初始化？
- HTTP 加载、WebGL2 编译和素材解码是否正常？
- 代码、照片、字体、音频分别记录来源。保留 MIT 代码许可，原曲不作为 skill 资产分发。
- 提供作品入口、运行方式、验证结果和仍未验证的导出或性能限制。
